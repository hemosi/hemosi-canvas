# 爆款复刻功能集成计划书（HemosiTV × Hypit）

编制日期：2026-11-13｜拍板：hemosi｜执行：Hark（或其他执行 AI）｜验收：Muse 实测｜沿用 TASKBOOK-tapnow-2026-11-10 的角色与硬约束

## 本版修改（2026-11-13）

原稿结构、路线 A → B、Hypit 外挂全部保留。文本、图像、视频模型照现有渠道配置，不改。只改非模型接口：**转写（ASR）、配音（TTS）这类接口，同接口本地优先**。正文对应处已改写并标【本地优先】。

1. **转写默认本机。** 走 OpenAI 兼容 `/v1/audio/transcriptions`（请求词级时间戳 `timestamp_granularities[]=word`），默认指向本机 faster-whisper 类服务，本机地址不要求填 Key；付费 ASR 接口保留为可选。接口只给句级时间戳时照样出蓝图和 SRT，蓝图标注「无词级时间戳」。
2. **理解层用现有模型。** 原稿写「官方多模态 LLM」处，改为沿用画布已配置的模型渠道，不新增分析专用接口。
3. **确认卡口径。** 转写走本机时写「本机处理，无费用」；模型调用照现有生成确认卡计费口径。
4. **Hypit 路线 B 保留。** 其中转写用 Hypit 自带的本地 WhisperX（需 uv 与 Python），配音指向本机 TTS 服务；不用 HypiHub 等聚合服务做 ASR/TTS。模型调用照现有渠道。

## 0. 一页读懂

**要做什么**

在 HemosiTV 无限画布里新增「爆款复刻」动线：导入一条爆款视频 → 拆解成可编辑的「爆款蓝图」（钩子、节奏、分镜、台词、字幕风格）→ 蓝图自动长成画布节点 → 替换人物 / 话题 / 产品 / 语言 → 批量出变体 → 导出成片或分镜素材包。

**三条核心判断**

1. **Hypit 的“复刻”不是一条命令。** 它分三段：编程 Agent（Claude Code、Codex 等）加载 Hypit Skill 读懂参考视频 → Agent 写出 SVML 源文件 → `hypit` CLI 编译渲染。前两段靠 Agent 的理解与写作，没有一个可以直接调用的 clone 接口。
2. **HemosiTV 的底盘决定“理解层”应在画布里原生实现。** 项目无后端、浏览器直连官方 API、数据存 localforage，硬约束是只接官方 API、无注册墙、双击安装。Hypit 需要 Node ≥ 22.15、FFmpeg，本地转写还要 uv 与 Python，只适合做可选的“合成层”外挂。
3. **Hypit 许可证限制再分发。** 它是修改版 Apache-2.0：对外托管多租户服务、以营利方式再分发（含捆绑进产品交付第三方）需要商业授权。对策：不拷贝源码、不打进安装包，由用户自行 npm 安装，画布探测后调用。

**推荐路线：A 先行，B 后接**

- 路线 A：原生蓝图复刻（不依赖 Hypit）。视频 → 蓝图 → 画布节点 → 变量替换 → 批量生成 → 导出素材包。独立交付价值。
- 路线 B：Hypit 外挂合成引擎（可选）。负责 A 做不了的“词级锚定字幕、动效、整片合成渲染”。B 失败或被砍，不影响 A。

**基线声明（重要）**

本计划依据的是我抓到的 hemosi-canvas 旧快照（约 v0.21.2、49 次提交）。你屏幕上已是 v0.21.6（55 次提交），其中新增的「in-canvas Director Loop / Director Group」我没读到。M0 必须先重读最新 main 再校准本计划；凡标注「待 M0 核实」的，都是我没能确认的点。

## 2. 路线选型

| 维度 | A 原生蓝图复刻 | B Hypit 外挂合成 | C 把 Hypit 并进项目 |
| --- | --- | --- | --- |
| 做什么 | 画布内完成理解、拆解、变量替换、批量生成 | 把蓝图与素材交给 Hypit，合成带词级字幕与动效的成片 | 复制或打包 Hypit 源码进项目 |
| 依赖 | 本机 ASR（OpenAI 兼容接口，付费可选）【本地优先】、现有模型渠道 | 用户本机装 Node ≥ 22.15、FFmpeg、`@hypit/hypit`，外加 Agent | 同 B，且随安装包分发 |
| 双击安装 | 满足 | 部分满足（可选功能，需用户自装） | 不满足 |
| 许可证风险 | 无 | 低（不分发 Hypit） | 高（触碰再分发条款） |
| 契合 AGENTS.md | 高（浏览器直连、官方 API、localforage） | 中（需桌面桥，打破“无后端”假设，须拍板） | 低 |
| 失败代价 | 低 | 低（可整体砍掉） | 高 |
| 结论 | 先做，M1–M6 | 后接，M7 | 不采用 |

**推荐 A → B。** A 覆盖“爆款拆解、替换、批量”这一最核心的价值，且完全落在现有底盘内；B 只补合成层，价值明确但环境与许可证成本高，适合 A 稳定后按需接入。

## 3. 总体架构

**路线 A 数据流**

```
本地视频文件 ──► 源视频节点
      │ ① 预处理（浏览器：抽帧 + 切点检测 + 音频抽取）
      ▼
 复刻分析节点
      │ ② 本机 ASR（OpenAI 兼容接口，付费可选）：词级时间戳台词【本地优先】
      │ ③ 已配置的多模态模型：读钩子、结构、节奏、分镜、字幕风格
      ▼
 爆款蓝图 Blueprint（JSON，zod 校验，可手改）
      │ ④ 展开
      ▼
 分组「复刻工作组」
   ├─ 文本节点：台词稿
   ├─ 锚点节点：角色 / 场景 / 风格（只写文字设定）
   ├─ 分镜节点 × N：每个 beat 一个
   └─ 变量面板（复刻分析节点侧栏）
      │ ⑤ 替换变量  ⑥ 生成确认卡（汇总费用）  ⑦ 官方 API 生成（沿用现有队列）
      ▼
 图片 / 视频结果节点 ──► ⑧ 导出分镜素材包（片段 + SRT + 蓝图 JSON）
```

**路线 B 追加链路（桌面版、可选）**

```
蓝图 + 变量值 + 已生成素材
   → 桌面桥（IPC）准备 Hypit 工作区
   → Agent 步骤：canvas-agent 驱动 Codex，加载 Hypit Skill，写出 .svml / .svrun
   → hypit check → plan → pricing --json → 确认卡
   → hypit build → status → inspect → get
   → 成片导入为视频节点（原节点保留）
```

**分层原则**

- 理解层（蓝图）是产品资产，永远在画布内，与 Hypit 无关。
- 合成层（Hypit）可替换：以后换别的合成引擎，蓝图与节点不用改。
- 所有会花钱的步骤，包括“分析”本身，都走现有的「生成前确认卡」。

## 4. 数据模型

### 4.1 爆款蓝图 Blueprint

蓝图是整个功能的核心资产，用 zod 定义并校验，独立带 `schemaVersion`。

| 字段 | 内容 |
| --- | --- |
| `meta` | 标题、时长、画幅、帧率、语言、体裁、源视频哈希（只存哈希，不存原片） |
| `hook` | 开场钩子：起止时间、类型（提问 / 反差 / 震惊 / 承诺等）、文案、画面描述 |
| `beats[]` | 节奏单元。每个含：`id`、序号、起止时间、角色（钩子 / 铺垫 / 论证 / 转折 / 兑现 / 行动号召）、台词（整句 + 词级时间戳）、镜头（类型：真人出镜 / B-roll / 图形 / 屏幕录制 / 字幕卡；画面描述；景别、角度、运镜；屏上文字）、声音提示（BGM、音效）、关键帧引用、关联变量 |
| `characters[]` | 角色：`id`、称呼、定位（主持 / 嘉宾等）、外形文字设定、声线描述、是否真人（真人时默认不把其人脸当生成参考） |
| `scenes[]` | 场景：环境、光线、色调 |
| `style` | 字幕（版式、字体感、逐词 / 整句高亮、配色）、剪辑节奏（平均镜头时长、快慢）、BGM 情绪、转场 |
| `variables[]` | 可替换槽位：键、标签、类型（文本 / 图片 / 枚举 / 语言 / 画幅）、默认值、作用范围（哪些 beat 或节点） |
| `provenance` | 分析所用模型、ASR 模型、生成时间、应用版本、`schemaVersion` |

要点：

- 台词保存词级时间戳，这是 A 路线导出 SRT、B 路线锚定字幕的共同基础。
- 蓝图可被人工编辑。模型输出错了，用户改蓝图比重新分析便宜。
- 不存源视频原片与源声音，只存哈希、文字描述和（用户确认后才保留的）关键帧。

### 4.2 蓝图到节点的映射

| 蓝图元素 | 画布节点 | 说明 |
| --- | --- | --- |
| 源视频 | 视频节点（已有） | 作为复刻入口，保持原样 |
| 整份蓝图 | 新增「复刻分析」节点 | 展示状态、蓝图摘要、变量面板；蓝图 JSON 的编辑入口 |
| 工作组 | 分组节点（已有） | 框住本次复刻生成的全部节点 |
| 台词 | 文本节点（已有） | 一段完整台词稿，可被 @ 引用；词级时间戳放元数据 |
| `characters[]` / `scenes[]` / `style` | 锚点节点（角色 / 场景 / 风格） | 只写文字设定；是否有参考图由用户另行添加 |
| 每个 beat | 分镜节点 | 镜头号、画面描述、提示词、参考图槽、结果槽 |
| 关键帧 | 图片节点（用户勾选才创建） | 默认不进画布，见 9.2 |
| `variables[]` | 复刻分析节点的变量面板 | 改值后重新展开提示词，不重跑分析 |

若 M0 查明分镜 / 锚点节点尚未落地，M4 先补最小版（字段见 TASKBOOK 第一部分二.5、二.6），或暂用「文本节点 + 图片节点 + 元数据」降级承载，由你在 M0 之后拍板。

### 4.3 存储

- 蓝图、关键帧 blob、分析中间产物一律用 `localforage`，不进 `localStorage`。
- 键名建议：`clone:blueprint:<projectId>:<nodeId>`、`clone:frames:<projectId>:<nodeId>`。
- 蓝图 `schemaVersion` 与应用版本独立；项目尚未上线，**不写旧版兼容与迁移**（AGENTS.md 规定），格式变了直接按新设计改。
- 画布导出包需包含蓝图；是否含关键帧由用户在导出时勾选。

## 5. 用户动线

1. **导入**：把本地视频文件拖进画布，或在视频节点右键选「复刻为爆款蓝图」。v1 不做平台链接下载（见 9.3）。
2. **预估**：弹出「分析确认卡」，显示视频时长、将送出的关键帧数与音频时长、所选分析模型与渠道、预估费用。确认后才开始。
3. **分析**：进度依次显示「抽帧 → 切点 → 转写 → 理解」，可取消，失败时显示原始错误原文。
4. **看蓝图**：复刻分析节点展示摘要（钩子、节奏、beat 数、角色、风格）；点开可编辑蓝图每个字段。
5. **展开**：点「展开到画布」，生成「复刻工作组」（文本、锚点、分镜）。展开可重复：再次展开会新建一组，不覆盖旧组。
6. **替换**：在变量面板改主持人设定、话题、产品、语言、画幅；改动实时反映到各分镜提示词。
7. **生成**：选分镜或整组发起生成，走现有「生成确认卡」，卡上能看到每镜用哪个模型、哪个渠道、完整提示词。
8. **变体**：变量表按行添加变体，一键批量展开；统一确认费用后入队。
9. **导出**：导出分镜素材包（按镜头号命名的片段、SRT 字幕、蓝图 JSON）；装了 Hypit 的桌面版可再选「合成成片」（路线 B）。

## 7. Hypit 外挂集成细则（路线 B）

### 7.1 探测与版本

- 桌面桥新增 `hypit:probe`：依次执行 `hypit --version`、`hypit version --check`（旧版用 `npm view @hypit/hypit@latest version`）、`node --version`、`ffmpeg -version`。结果缓存，设置页显示「就绪 / 缺什么 / 安装命令」。
- 画布永不自动安装任何东西。缺 Node、FFmpeg、Hypit 时只展示命令，由用户自己装（`npm install -g @hypit/hypit`，要求 Node ≥ 22.15）。需要本地 WhisperX 时才提示 uv。
- 版本守卫：写死兼容区间（初值 0.3.x，M0 之后以实测为准）；区间之外只警告并禁用「合成成片」，不尝试运行。

### 7.2 工作区

- 位置：桌面版用户数据目录下 `hypit/<projectId>/`（具体路径待 M0 与桌面外壳约定）。
- 初始化：写 `package.json`（项目边界）与 `.gitignore`（`.hypit/`、`output/`）；执行 `hypit runtime init`（不会覆盖已有文件）与 `hypit runtime use hypit.runtime.json`；需要时 `hypit runtime up`。
- 目录沿用 Hypit 推荐布局：`authors/`、`runs/`、`assets/`、`output/`；蓝图放 `assets/blueprint.json` 供 Agent 读取。
- 画布素材进工作区：只复制必要文件到 `assets/`；每个引用图或视频都带「含真人」标注。

### 7.3 Agent 步骤（谁来写 SVML）

| 方案 | 做法 | 评价 |
| --- | --- | --- |
| a. canvas-agent 桥 + 本地 Codex + Hypit Skill | 画布把「复刻任务」发给桥，桥在工作区里启动 Codex，Codex 按 Skill 写 `.svml` / `.svrun` | **推荐**：复用现有基建；但桥标注「未验通」，需 M0 实测 |
| b. 用户自备 Claude Code / Codex 终端 | 画布只准备工作区和任务说明，用户在终端执行 `/hypit …` | 最稳、代码最少；体验割裂 |
| c. 应用内 LLM 直接写 SVML | 不推荐：DSL 变动快（0.3 到 0.3.1 就有迁移），且缺 Skill 的整套生产知识 | 否决 |

给 Agent 的任务模板：

```
/hypit 以 assets/blueprint.json 为结构参考，已生成的镜头素材在 assets/shots/。
按蓝图的节奏与字幕风格合成成片，台词与替换变量以 blueprint.json 的 variables 为准。
目标输出 final.video。只做 check 与 plan，不要 build；把 pricing 结果写到 output/pricing.json。
```

关键纪律：Agent 只负责写源文件并 `plan`，**`build` 必须由画布在用户确认费用后触发**。画布只信产物、不信自述：`hypit check` 不通过就不往下走。

### 7.4 命令编排

| 步骤 | 命令 | 画布行为 | 失败处理 |
| --- | --- | --- | --- |
| 1 | `hypit doctor` | 设置页「环境自检」 | 展示缺项，不阻断 A 路线 |
| 2 | `hypit check authors/main.svml` | 校验 Agent 产物 | 把诊断文本回喂 Agent，最多 N 轮（第 8 节待确认） |
| 3 | `hypit plan runs/final.svrun` | 展示将执行的工作 | 非零退出码即预检失败，展示 preflight 原文 |
| 4 | `hypit pricing runs/final.svrun --json` | 解析 `groups[].requests` 生成确认卡，未知价格标「未知」 | 价格读取失败要显式展示，不得当作 0 |
| 5 | 用户确认后 `hypit build runs/final.svrun --title <名称>` | 拿到 build id，登记进队列 | 提交失败展示原文 |
| 6 | `hypit status <build-id> --watch` | 进度进队列视图 | 观察进程被关掉不影响 build 继续跑 |
| 7 | `hypit inspect <build-id>` | 读目标与失败证据 | 失败原文进队列 |
| 8 | `hypit get <build-id> --output final.video --to <路径>` | 成片导入为视频节点 | 目标路径已存在则拒绝（Hypit 自身规则） |
| 9 | `hypit cancel <build-id>` | 用户取消 | 仅在执行上下文仍可用时有效 |

### 7.5 进程管理与安全

- 一律用「可执行文件 + 参数数组」启动子进程，禁止拼接 shell 字符串；工作目录固定为项目工作区。
- 传给子进程的环境变量用白名单；日志进队列前脱敏（Key、令牌、用户目录路径）。
- 所有路径限定在工作区内，防路径穿越；用户给的文件名先规范化。
- 超时、轮询间隔、最大并行 build 数见第 8 节，未经确认不得落地。
- 取消等于 `hypit cancel` 加结束进程树；应用退出时询问是否执行 `hypit runtime down`。
- Hypit 的 Worker 是后台常驻进程，桌面外壳要管理其生命周期，避免残留。

### 7.6 凭据

- 画布不读、不写 Hypit 的凭据文件。
- 方式一（推荐）：用户在终端执行 `hypit auth login <凭据引用>`；画布用 `hypit auth status <引用>` 只显示「已 / 未配置」。
- 方式二：在 HemosiTV 设置里填 Key，仅在启动子进程时以环境变量注入，不写入工作区。注意 HemosiTV 的 Key 存浏览器本地（AGENTS.md），属明文存储，界面必须写清这一点。
- 任何 Key 都不得出现在 `.svml`、`.svrun`、运行时配置与提交文件中。

### 7.7 渠道与计费

- **冲突**：hemosi 的硬约束是「生成渠道必须是官方 API 或自有环境，不接带返利链接的中转站」。Hypit 推荐的 HypiHub，以及 TokenDance、HiAPI、Pollo、Monid 等，属于聚合服务，其 README 里还带邀请链接，**默认不启用**。
- 做法：M7a 先清点 Hypit 现有 Provider，标出官方直连的；其余要么由 Agent 按官方文档写项目内 Provider，要么不启用。清点结果交 hemosi 拍板。
- 费用：确认卡分两栏——「HemosiTV 官方渠道（A 路线生成）」与「Hypit 合成步骤（若含生成调用）」。纯代码渲染的合成步骤不产生模型费用，需如实显示为「无模型调用」。
- 预估永远附带「未知项」说明：`pricing` 只读取价格，不保证总价。

### 7.8 结果回填

- 成片由 `get` 导出到工作区 `output/`，再作为视频节点导入画布，节点元数据记 `source: hypit`、build id、所用 `.svrun`。
- 原有分镜节点与结果全部保留，成片是新增节点，不覆盖任何东西。
- 工作区默认不进画布导出包；用户可勾选带上 `.svml` / `.svrun`，方便在别处重跑。

### 7.9 失败、取消与复用

- Hypit 没有隐式缓存，也不续跑。失败后已完成的产物仍在 Result 里；画布用 `inspect` 与 `history <输出名>` 找到可复用的产物。
- 重跑等于新建 `.svrun`，用 `build-record` + `satisfy` 显式复用已完成产物，再 `plan` 看清只会重做哪些步骤，再确认费用。
- 界面文案不得写「已断点续传」，要写「已复用 N 个已完成产物，其余重新生成」。

### 7.10 版本守卫与升级

- 固定精确版本；升级前读 `migrations/` 下的迁移指南与发布说明；升级后重跑环境自检与一次冒烟。
- Skill 与 CLI 两条更新通道相互独立，探测时两者版本都要显示。

## 8. 边界值与费用控制（全部待你确认）

AGENTS.md 规定：新增或调整超时、重试次数、大小限制、并发上限前，必须先说明适用环节、默认值和失败处理，并取得确认。下表是建议值，**确认之前执行方不得写进代码**。

| 项 | 适用环节 | 建议默认值 | 超限或失败时 |
| --- | --- | --- | --- |
| 源视频时长上限 | 导入 | 90 秒 | 拒绝，提示先裁剪 |
| 源视频文件大小上限 | 导入 | 300 MB | 拒绝，提示压缩 |
| 切点采样间隔 | M2 | 0.2 秒 | 无（可调） |
| 送分析的关键帧上限 | M3 | 48 张 | 均匀降采样，并在确认卡标明 |
| 送 ASR 的音频大小上限 | M3 | 20 MB（16 kHz 单声道约 10 分钟，90 秒视频远低于此） | 报错，不截断 |
| 分析请求超时 | M3 | 120 秒 | 报错，保留已完成的中间产物 |
| 蓝图校验失败重试 | M3 | 1 次（带错误回喂） | 仍失败则保留原始输出供手改 |
| 单次批量变体上限 | M5 | 20 个 | 拒绝并说明 |
| 复刻批量生成并发 | M5 | 3 | 其余排队 |
| Agent 修正 `check` 的最大轮数 | M7b | 3 轮 | 停止并交还给用户 |
| Hypit build 超时 | M7c | 30 分钟 | 提示，可取消，不自动终止 |
| Hypit 状态轮询间隔 | M7c | 3 秒 | 无 |
| 最大并行 Hypit build | M7c | 1 | 其余排队 |

**费用控制原则**

- 凡是花钱的步骤，包括「分析」本身，都先弹确认卡。
- 批量变体一律汇总成一张确认卡，显示总镜数与预估总价；价格有未知项时必须明说。
- 任何超限一律拒绝并说明，不静默截断、不静默降级。

### 9.1 Hypit 许可证

依据我读到的 LICENSE 摘录（执行前必须读原文再确认）：这是修改版 Apache-2.0，附加条件有：

- 未经书面授权，不得用 Hypit 源码或其衍生作品运营多租户环境，或把其功能作为托管 / SaaS 提供给第三方；
- 未经书面授权，不得出售、收费许可或以营利为目的提供 Hypit 或其衍生作品，无论独立还是捆绑进交付第三方的产品；
- 允许 fork、修改并发布，但须以同一许可证发布，且不得营利性提供；
- 用 Hypit 产出的视频、音频、图片等产物归使用者，商用不受该许可证限制；
- 其余遵循 Apache-2.0。

补充说明：README 徽章写的是「Apache-2.0 with conditions」；网上有人把它重新授权成标准 Apache-2.0 的 fork，**那些 fork 不能当作授权依据**。Hypit 的 issue #281 里有开发者为小程序产品正式申请商业授权，可见多租户式用法确实被视为需要授权。

| 做法 | 理由 |
| --- | --- |
| 不拷贝 Hypit 源码进 hemosi-canvas | 避免形成衍生作品与再分发 |
| 不把 Hypit 打进安装包，由用户自行 npm 安装 | 避免「捆绑交付第三方」 |
| 只通过 CLI 子进程调用 | 松耦合，随时可以下线 |
| 保持自用，不做账号制托管服务 | 对应 TASKBOOK「自用工具，不做账号生意」 |
| 将来要上线托管、卖安装包或对外收费时，先向 Hypit.AI 取得书面授权 | 许可证明文要求 |

我不是律师，以上是对条款的工程层面解读。涉及商业化之前，请自己或请法务核对原文。

### 9.2 版权与肖像

- 复刻是学结构，不是搬内容。默认只提取结构、节奏与文字描述，不把源视频帧或人声当生成参考。
- 用户勾选「我拥有该素材的使用权」后，才允许把关键帧作为参考图，并强制逐张标注「含真人」（对应 Seedance 的 person-reference 要求）。
- 不提供「换成真实他人的脸」或「克隆真实他人声音」的预设与引导文案。
- 首次使用时提示：复刻他人作品存在版权、肖像权与平台规则风险，发布前请替换人物、文案与素材。

### 9.3 来源链接

v1 只支持本地文件与拖入。平台链接下载涉及反爬与平台条款，而 Hypit 对「支持的平台链接」的具体处理方式我没读到细节，是否做另行拍板，不自作主张。

### 9.4 MIT 基底与第三方依赖

- 沿用 basketikun/infinite-canvas（MIT）声明，LICENSE 保持不动。
- 新增依赖（zod、zip 库；若引入 ffmpeg.wasm，需单独核对其 LGPL / GPL 构建差异）一律记入第三方许可证清单。

### 9.5 数据与隐私

- 源视频只留在本地，不上传到任何自有服务；蓝图与关键帧存浏览器本地。
- 分析时，关键帧与音频会发给你配置的官方 API，首次使用时明确告知。

## 10. 风险登记

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| Hypit 的 DSL、SDK 变动快 | 路线 B 随时可能失效 | 固定精确版本；外挂式耦合；A 路线完全不依赖它 |
| Agent 写出的 SVML 质量不稳 | 合成失败或效果差 | `check`、`plan` 作门禁；失败诊断回喂；限制轮数 |
| 多模态分析的 JSON 不稳定 | 蓝图缺字段或胡编 | zod 校验、错误回喂重试、用户可手改、保留原始输出 |
| 浏览器处理大视频卡顿或爆内存 | 画布卡死 | 时长与大小上限；放 Worker；可取消；分段处理 |
| 官方 ASR 无词级时间戳或有限额 | 字幕与对时能力下降 | M0 选型；备选用桌面桥跑本地 WhisperX（Hypit 自己也用它） |
| Director Loop 与本功能重叠 | 重复造轮子、行为冲突 | M0 重读；优先复用其循环与暂停确认 |
| Electron 内置 Node 低于 22.15 | 无法用内置 Node 跑 Hypit | 用用户机器上的 Node；探测并提示 |
| Hypit 许可证 | 触碰再分发或托管条款 | 见 9.1：不拷贝、不捆绑、自用 |
| 费用失控（分析、批量、合成叠加） | 账单意外 | 全程确认卡、批量上限、预估带未知项说明 |
| 命令注入、路径穿越、密钥泄露 | 本机安全 | 参数数组启动、路径白名单、环境白名单、日志脱敏 |
| 版权与肖像纠纷 | 法律风险 | 见 9.2：默认只学结构，所有权勾选，不提供换脸 / 克隆声音 |
| canvas-agent 桥「未验通」 | 路线 B 的 Agent 步骤落空 | M0 实测；不行就退到方案 b（用户自备终端） |

## 11. 验收清单（Muse 实测，不看自述）

路线 A：

1. 拖入一条 60 秒口播视频，右键「复刻为爆款蓝图」，弹出分析确认卡，时长、帧数、音频时长、模型、渠道、预估费用齐全；点取消则网络面板里零请求。
2. 确认后分析完成：蓝图通过校验；beat 数与人工分段偏差不超过 1；钩子被识别；台词词级时间戳抽查 5 处都对得上。
3. 点「展开到画布」：生成台词文本节点、角色 / 场景 / 风格锚点、N 个分镜节点；镜头号与 beat 一一对应，连线语义正确；再次展开会新建一组，旧组纹丝不动。
4. 在变量面板改主持人设定与话题：所有相关分镜提示词立刻带新值，且不触发重新分析（零网络请求）。
5. 任选一个分镜发起生成：确认卡里的模型、渠道、完整提示词与所设一致；模型不可用时报出 `modelNotReadyReason` 的原因，不悄悄换模型；失败显示原文原因，改参数可一键重跑。
6. 变量表加 3 行变体，批量展开 3 组，统一确认卡汇总镜数与费用；超出上限被拒绝并说明。
7. 批量中途故意让一个失败：队列显示原因，其余不受影响；重跑成功；各变体版本互不覆盖。
8. 导出素材包：zip 内有 `shots/`（文件名带镜头号）、`captions.srt`（带「草稿，非精确对时」说明）、`blueprint.json`、`README.txt`；导入剪映或播放器抽查可用。
9. 整体：项目关闭重开，蓝图、节点、变量、版本完整；导出再导入项目包无缺失。
10. 整体：控制台零报错；新增 UI 文案全中文；浅色与深色主题下都正常（不硬编码颜色）。

路线 B（仅在做 M7 时验）：

11. 设置页环境自检：未装 Hypit 时给出安装命令与缺项，A 路线不受影响。
12. Agent 产物通过 `hypit check`；查命令日志，全程没有触发 `build`。
13. 确认卡费用与 `hypit pricing --json` 一致，未知项明确标注；确认后才 `build`；成片作为新视频节点回填，原节点保留。
14. 取消 build 后无残留进程；失败后重跑的文案是「已复用 N 个产物」而不是「续传」。

安全与合规抽查：

15. 子进程以参数数组启动；日志里没有 Key；文件名含 `../` 的样例被拒绝。
16. 默认不把源视频人像帧当生成参考；未勾选所有权前不可选；没有换脸或克隆声音的预设。
